# Журнал боевых действий — трекер

Часть репозитория: общая карта — в корневом `README.md`. Команды ниже выполняются из папки `tracker/`.

Тактический трекер для настольных сражений. Пользователь получает один HTML-файл (`dist/tracker.html`), который открывается двойным кликом. Разработка ведётся в модулях.

## Структура

## Команды

```
npm install              один раз после клонирования
npm test                 сверка движка с эталоном v29
npm run check            всё сразу: тесты, сборка, сквозная проверка, Discord
npm run build            собрать dist/tracker.html
node tools/discord.mjs   dist/discord/part-N.md для публикации
node tools/smoke.mjs     проверить собранный файл целиком
npm run siege            пересобрать каталог осадных орудий для ГМа (shared/siege/catalog.md)
npm run discord:post     пробный прогон: как патчноут текущей версии ляжет в Discord (сообщения до 2000 символов)
npm run discord:post -- --send   отправить его в канал вебхуком (--version 30.8 — другую запись, --all — всю историю)
```

Node.js 22+ (нужен для `node --test` с шаблонами путей, в том числе на Windows). После клонирования — `npm install`: он поставит `jsdom` для инструментов `smoke` и `make-golden`; самому трекеру зависимости не нужны.

## Как устроена проверка формул

Эталонное тестирование (characterization testing): вместо того чтобы вручную выписывать ожидаемые числа, берётся работающая версия (v29), через неё прогоняются сотни сценариев с фиксированным зерном случайности, результат сохраняется как эталон. Любое изменение движка сверяется с эталоном построчно — вплоть до текста журнала.

Отсюда правило: **если меняешь формулу намеренно, тест упадёт — это нормально.** Тогда формула должна уйти в новый набор правил (`rules.js`), а набор 1 остаётся нетронутым и продолжает совпадать с v29.

## Наборы правил

Все числа из формул лежат в `src/engine/rules.js` в объекте `BASE_RULES`. Чтобы сделать набор 2 или 3, достаточно скопировать объект, изменить нужные числа и зарегистрировать его в `RULESETS`. Если меняется не число, а сама логика — в правиле появляется флажок, и `combat.js` ветвится по нему.

## Сбор армий из текста

Три шага, все в движке и все проверяются без браузера:

1. `parseArmyText` — текст → стороны → контингенты → строки «число + название». Строка с запятой в конце — фракция, строка без числа — полководец, «+» — союзный контингент, «VS» — следующая сторона, «=» — итог для сверки.
2. `planMuster` — каждой строке подбирается шаблон (`matchTemplate`) и тип войск (`guessUnitType`). Это черновик: интерфейс показывает его в предпросмотре, и мастер правит всё до сбора.
3. `expandMuster` — нарезка на отряды по размеру из шаблона, нумерация «№N» (своя в каждой фракции), характеристики из шаблона с правками фракции.

Новый формат текста — это сначала образец в `shared/battles` и тест в `muster.test.mjs`, потом правка разбора.

## Шаблоны отрядов

`BASE_TEMPLATES` в `templates.js` — черновик до ГМа, у каждого шаблона указано, по каким отрядам из сохранений Алекса он посчитан. Правки партии лежат в сохранении (`templateOverrides`): общие (`base`) и по названию фракции (`factions`). Итог: база → общие правки → правки фракции.

## Карта и местность

Местность — два слоя клеток по 5 м (`terrain.js`): вид местности (коды в `TERRAIN`, их нельзя перенумеровывать — они в сохранениях) и высота 0–3. В сохранении партии слои сжаты повторами (`battleMap`). Что клетка значит в бою — `rules.js`, раздел `map` (черновик до ГМа). Работает только при включённых «Правилах карты»: интерфейс считает `Engine.mapModsFor` и передаёт в бой необязательным `req.mapMods`, а в конец хода — `ctx.fatigueMult`. Без них движок считает ровно как v29 — это держит эталонный тест.

В интерфейсе карта — «окно» и «сцена» внутри него: сцена = окно × приближение, фишки стоят на сцене в процентах. Местность рисуется холстом размером с окно между картинкой и фишками. Генераторы (`mapgen.js`) — функции от настроек и зерна: одно зерно — одна карта. Стена крепости — клетки внутри формы, у которых хотя бы один из восьми соседей снаружи: такое кольцо не обойти ни прямо, ни по диагонали (это проверяет тест). Участки стен (6б, `fortify.js`) — третий слой карты: номер участка в каждой клетке стены, частокола, ворот и башни (`m.s`) и список участков с полученным уроном (`m.forts`). Прочность — в `rules.js` (`siege.hp`), в карте только урон: поправка чисел ГМом не требует пересобирать карты. Связная стена режется по пути вдоль неё на равные участки не длиннее `siege.sectionM`; кольцо, сошедшееся «рукавами», режется повторно. Участки строятся при первом взгляде на карту со штурмом (`ensureSections`), после правки в редакторе — заново, урон переходит к участку, где лежит большинство его прежних клеток. Обнуление прочности — пролом: клетки становятся местностью «пролом», и путь, обзор и бой видят его без особых правил. Редактор — полноэкранный режим с тем же рисованием; свои шаблоны карт живут в отдельном ключе браузера (`battle_tracker_maps_v1`), чтобы не попадать в снимки отката и переживать «Сбросить всё».

## Патчи

У каждого патча — короткое название, передающее суть. Номер версии в `package.json`, название патча и обновления — в `tools/build.mjs` (`RELEASE`).
