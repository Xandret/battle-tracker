# Инструкции для Claude Code

Проект — «Журнал боевых действий», тактический трекер для настольных сражений. Полный план — в `SPEC.md`, устройство — в `README.md`. Прочитай оба перед началом любого этапа.

## Как мы работаем

- Пользователь — **Алекс**. Язык проекта, интерфейса, журналов, патчноутов и коммитов — **русский**; английские термины допустимы там, где русский перевод неудачен.
- Работаем в паре: ты пишешь код и делаешь работу вместе с Алексом. Объясняй решения подробно и на конкретике — он учится на этом проекте. Если он прямо просит не решать за него, переходи на подсказки.
- Спорь, если идея слабая и есть весомые аргументы против; при спорных решениях давай варианты с плюсами и минусами.

## Жёсткие правила

1. **Движок не знает о браузере.** В `src/engine/` нет DOM, `localStorage`, `Math.random`. Случайность — только через `ctx.rng`, чтобы тесты и симуляции были воспроизводимы.
2. **В интерфейсе нет боевой математики.** `src/ui/app.js` собирает ввод, зовёт `Engine`, применяет патчи, рисует.
3. **Набор правил 1 заморожен.** `tests/engine.test.mjs` сверяет его с эталоном v29 построчно. Если тест упал из-за намеренного изменения формулы — формула уходит в набор 2/3 или за переключатель, а не правится в наборе 1.
4. **Формулы — через ГМа.** Любая новая или изменённая формула боя — только как черновик (набор 2/3 или переключатель) до одобрения ГМом. Цифры-черновики помечай в патчноуте.
5. **Сохранения не ломаем.** Ключ `localStorage` — `battle_tracker_v13`. Новые поля получают значения по умолчанию в `applyLoadedState`; старые TXT-выгрузки должны открываться.
6. **Каждое новое правило — в `rules.js`**, а не числом в формуле.

## Перед тем как сказать «готово»

```
npm test                  # эталон v29 + новые тесты — всё зелёное
npm run build             # dist/tracker.html собирается
node tools/smoke.mjs      # сквозная проверка собранного файла
node tools/discord.mjs    # патчноут режется на части ≤ 4000 символов
```
Новую механику покрывай тестом на сидированном генераторе. Новую функцию интерфейса — проверкой в `tools/smoke.mjs`.

## Патчи

- У каждого патча — **лаконичное название, передающее суть** (пример: v30.0 «Фундамент»). Большое обновление целиком — «Пушки и крепости».
- Номер версии — `package.json`; название патча и обновления — `RELEASE` в `tools/build.mjs`.
- Запись в `PATCHNOTES.md` сверху, формат Discord: `#` заголовок с версией и названием, `-#` подпись, разделы `## 🆕 Новое`, `## ⚖ Изменения механик` (формулы в блоках кода, «было → стало»), `## 🛠 Исправления`, `## ⚠ Известные проблемы`.
- Когда этап закрыт, обнови таблицу статусов в `SPEC.md`.
